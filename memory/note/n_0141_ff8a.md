# Note: n_0141_ff8a

Native macOS webcam lane (landed): Swift camera host in EXAMPLE app only (jsr.camera MethodChannel, MainFlutterWindow.swift, AVCaptureSession → ≤320-wide RGBA @24fps), JS pull via jsr.hostCall('camera.frame') JSON/base64 (hostCallBinary is JS→Dart only — no Dart→JS bytes lane), adapter tool/three_example/degrades/webcam_host.mjs applied to three-morphtargets-webcam + three-materials-video-webcam; graceful fallback byte-identical; MediaPipe face-tracking stays honestly stubbed (out of scope). TCC FACTS: macOS camera grant for ad-hoc-signed apps is keyed to the cdhash — ANY codesign re-sign invalidates it; prompts appear ONLY on user-initiated Finder launches (open-from-shell auto-denies without dialog, responsible-process attribution); capture env via Info.plist LSEnvironment + lsregister -f + re-sign (re-sign then breaks grant — order matters: re-sign FIRST, user re-grants ONCE, then never re-sign); JSR_CAMERA_LOG=<path> writes lane diagnostics to a file (stdout is lost for open/Finder launches). Live-acceptance test: two captures minutes apart must DIFFER (static renders are byte-identical); flat single captures can mislead.
