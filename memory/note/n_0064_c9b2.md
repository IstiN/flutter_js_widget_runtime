# Note: n_0064_c9b2

ROOT CAUSE of the 'fa-craft empty blue world on iOS' report (2026-10-20, fixed in c329d9d → jsr 0.4.172): the voxel painter drew ALL terrain via canvas.drawVertices(BlendMode.modulate, no shader — fa-craft sends texture:false); on iOS Impeller (mandatory since Flutter 3.29) that pipeline drops the geometry entirely (flutter/flutter#127486 family) — the painter still runs (~14k tris, 11ms/frame) but nothing rasterizes, so the user sees sky + alive HUD. macOS Impeller and flutter_test render the same call fine — that is why every local harness (QuickJS CLI, flutter test, JSC probe on macOS) stayed green. Fix: untextured opaque vertices draw BlendMode.srcOver (identical fill everywhere); textured keeps modulate. Field-diagnosis trick that cracked it: fa-craft's F3 overlay + Fa app logs show `uploads=25 native=true fps=7x` and `[voxel v=w5] paint=11ms tris=13896` — painting happening while the screen is empty = raster-layer bug, not data/pump. Diagnostic env that reproduces end-to-end without a device: minimal `flutter create -e` macos app depending on js_widget_runtime by path, inline fa-craft imports, boot JsWidgetEngine, RepaintBoundary capture after 8s (the jsr example screenshot harness wedges on its huge pod tree; the minimal app builds in ~3 min; remember to strip app-sandbox from both .entitlements or /tmp reads fail).
