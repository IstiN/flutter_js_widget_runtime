# Note: n_0094_462c

THREE R1 fog is LINEAR-ONLY: tool/three/src/native_renderer.js:985 `_fog(scene)` throws `three.unsupported: fogType (R1 supports linear THREE.Fog)` for FogExp2 (isFog undefined). Consequence for webgl_points_billboards (r186): every renderer.render() throws before frame submit → prepared-widget verdict is DOCUMENTED-GAP (error-card shape identical to ShaderMaterial gaps), NOT a pipeline failure of points/textures. Everything else in that module is R1-clean per test/js_three_points_billboards_example_test.dart probe (official module body verbatim on shared runtime): PointsMaterial kind pointsBasic pointSize 35, alphaTest 0.5, transparent, sizeAttenuation, map disc.png 32×32 sRGB (official sprite byte-identical at example/widgets/three-interactive-points/disc.png, sha256 1f381671…), single 100-vertex points draw, linear THREE.Fog(0x000,100,800) substitute renders fine. Module sets NO blending (default NormalBlending — the AdditiveBlending concern was unfounded for r186). The widget was NEVER prepared (absent from prepare.mjs EXAMPLES + bin registry + pubspec; api_matrix prepared:false) — the test file skips the widget test with a PREP-MISSING reason and auto-activates once widget.js exists.
