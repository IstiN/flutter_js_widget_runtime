# Note: n_0123_10a6

three.js R1 runtime: CPU skinning rewrites the position attribute in place, so geometry.boundingSphere (bind pose) and the official examples' per-frame SkinnedMesh.computeBoundingSphere (which re-applies bones to the ALREADY-skinned attribute) both publish wrong frustum-cull bounds; IK-animated nodes (webgl_animation_skinning_ik head/hair) vanish at many camera angles. Fix: _applySkining in tool/three/src/native_renderer.js refreshes object.boundingSphere from an O(vertex) min/max scan of the skinned attribute BEFORE the `unchanged` early-return (the example's own recompute corrupts the sphere between renders, so the refresh must run on paused/duplicate renders too). Regression: test/js_three_animation_skinning_ik_example_test.dart (orbit sweep, head in draw plan at every angle).
