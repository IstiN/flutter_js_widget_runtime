# Note: n_0122_6b25

three-example prepare determinism gotchas: (1) prepare.mjs itself is a pinned input — ANY edit to tool/three_example/prepare.mjs (even comments) changes every widget's prepare_manifest.json, so run the full 303-widget bulk re-prepare (node tool/three_example/prepare.mjs <upstream_id> --source <three-src> --offline, sequentially; ~13min; expects OK=303/303) after the emitter is FINAL, then freeze it. (2) The CLI takes UPSTREAM example ids (webgl_loader_ifc), not widget dir names (three-loader-ifc) — map via prepare_manifest.json's `example` key. (3) --verify re-prepares into a temp dir and byte-compares outputs+manifest; run it per-widget for full-tree consistency. (4) assets/three/three.native.js is a pinned input rebuilt from tool/three/src — if a parallel session edits tool/three/src mid-sweep, --verify fails with 'inputs.assets/three/three.native.js' mismatches on whichever widgets were prepared around the write; re-prepare + re-verify once the bundle settles. (5) three-loader-ifc NEVER renders the real IFC in QuickJS (web-ifc needs WASM): it always draws the bounded native proxy box — captures are byte-identical before/after any asset-pipeline change; 'IFC proxy serves an empty body' is expected.
