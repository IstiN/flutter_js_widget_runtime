# Note: n_0119_c73d

THREE batch-2 tooling notes (2026-11-02): (1) example/lib/screenshot.dart gained JSR_EXTRA_WAIT=<seconds> env knob (added to the 2s initial wait and the 30s presented>=3 readiness cap) — needed because the readiness gate captures as soon as 3 frames present, which for slow-decode scenes (panorama 8K atlas) is still the pre-texture white window; default behavior unchanged. (2) test/support/three_quickjs_example_harness.dart bootSource() gained useIsolate (additive). GOTCHA: bootSource + useIsolate with the default widgetId 'three-native-test' HANGS the probe (isolate lane asset/resolve path never resolves; test times out with buffered output); boot(widgetId: <real prepared widget>, useIsolate: true) works — use that for isolate-lane probes. flutter_test buffers test prints until the test completes, so a hung probe shows nothing. (3) Bulk re-prepare after a bundle rebuild: node one-liner reading example/widgets/*/prepare_manifest.json (.example key) and execFileSync'ing prepare.mjs <example> --source /tmp/jsr-three-r186 --offline — 303 widgets in ~13min, 0 failures (script pattern left at /tmp/three_issues/bulk_reprepare.mjs). (4) QuickJS micro-benchmarks via `dart run bin/jsr_widget.dart test <dir> --json` (widget.json {id,version,widget:{entry}} + widget.js using jsr.exportState) are the fastest way to time engine hot loops in the real QuickJS; decodeBase64 45MB: old 4318ms, table+narrow 2538ms, fused pair-table 2202ms, plus replaces skipped; jsr.b64encode 24MB = 558ms (already fast via pairs+join). (5) Log locations for this batch: /tmp/three_issues/*.log|*.png (captures, probes, benches, bulk-prepare logs).
