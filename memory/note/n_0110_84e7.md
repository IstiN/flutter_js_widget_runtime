# Note: n_0110_84e7

Flutter GPU/Metal: creating a command buffer per frame and then DISCARDING it unsubmitted (even unencoded) deadlocks the whole app after ~64-80 frames — main thread blocks forever in InternalFlutterGpu_CommandBuffer_Initialize → MTLCommandQueue commandBuffer semaphore. Diagnose with `sample <pid> 3` (main-thread stack shows the semaphore wait). Every created CommandBuffer must be submitted (or never created): multi-pass recording must not create a speculative initial buffer, and inactive shadow passes should submit their empty buffer. Repro/burn-in: example three_example supports --dart-define=JSR_THREE_AUTO=<ms> (cycles all sidebar examples) + JSR_SWITCH_LOG=true (FPS + firstFrame + full surface diagnostics); direct-boot alone did NOT reproduce — the leak showed at 120fps sustained after a selection switch.
