# Note: n_0143_3d95

Native macOS face tracking (2026-11-04): Swift `camera.track` hostCall (MainFlutterWindow.swift) toggles Vision VNDetectFaceLandmarksRequest on a dedicated serial queue with a drop-if-busy inFlight guard; per frame it deep-copies the CVPixelBuffer (capture queue recycles buffers) and ships COMPACT named-point geometry in the frame push/pull payload under `landmarks` (keys le/re eyes, lp/rp pupils, lb/rb brows, ol/il lips, fc contour, nc/no nose; box-normalized y-up, rounded 2dp, ~1KB). MAPPING LIVES IN DART: example/lib/camera_host.dart `faceSignalsFromLandmarks` (index-free: bboxes/centroids/x-extremes, so Vision point-order drift can't break it) emits 16 approximate Face Cap shapes (jawOpen, mouthSmile L/R, mouthFrown L/R, browInnerUp, browOuterUp L/R, eyeBlink L/R, eyeSquint L/R, cheekPuff, mouthPucker, noseSneer L/R) + lookX/lookY (official In/Out/Up/Down sums averaged, sign +hx=subject-left, lookX=−hx); FaceSignalSmother lerps 0.35 + rounds 3dp; shapes/lookX/lookY ride camera.frame responses ONLY while tracking live (bytes unchanged otherwise). JS: webcam_host.mjs native branch lerps 0.3 + applies via morphTargetDictionary, eyes at official 30° limit; mesh discovery rides a NEW Mesh facadeWrap (morphtargets-webcam entry only, prepare.mjs) calling __jsrWebcamHostMorphMesh; face resolved lazily by name mesh_2/eyeLeft/eyeRight (GLTFLoader fills morphTargetDictionary AFTER construction); first mesh registration sends camera.track; stopPull sends enable:false. Node test seams: __jsrWebcamHostApplySignals/__jsrWebcamHostFaceState. Tests: tool/three_example/test/webcam_host_test.mjs (+5 face blocks), test/camera_host_face_signals_test.dart (16). APPROXIMATE only — not MediaPipe grade; gaze/blink sign sanity is verified by the live jsr-shot2 round-trip, not CI.
