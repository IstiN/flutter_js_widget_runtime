# Note: n_0049_34de

VoxelPainter (js_voxel_node.dart) hot-path rework in 0.4.131 (commit c4f3b4e): the per-frame bottleneck for fa-craft-scale scenes (200-400k triangles) was one Path()+drawPath per triangle (~300k canvas calls) plus Offset/Color allocation churn. Now: (1) triangles sort by an ARITHMETIC-packed key ((inverted depth bucket)*2^32 + argb) — NEVER bitwise: dart2js bitwise ops are 32-bit and shred high bits; (2) the draw loop emits ONE Path per (bucket,color) run — painter order kept at 1024-bucket granularity; (3) _Tri stores flat Float32List(6) pts + int argb; (4) backface+subpixel (<~1/8 px^2) culling share one compare. Also: voxel.chunkRemove bridge capability (soft no-op on unknown key/instance) for widget-side eviction; gestureDetector.onScroll surfaces PointerScrollEvent as {dx,dy} (two-finger trackpad swipe / wheel) — fa-craft 0.2.3 maps it to 'look'. Diagnosis method that matters: the widget-side [facraft] prof line (hud/mesh ms) proved JS was at 0.1ms/frame while fps was 13 — the host painter was the bottleneck, not the bridge.
