# Note: n_0120_0549

FIXED (2026-11-02, supersedes the 2026-10-30 isolate-crash note): the three_example SIGABRT (DLRT_GetFfiCallbackMetadata ← qjs_bytes_dispatch ← qjs_eval, thread 15 DartWorker, crash report clip_1793630539629) root cause = dispose()'s stuck-eval backstop in lib/src/runtime/js_widget_engine_quickjs_isolate_vm.dart _shutdownWorkerLocked: after the 10s ack grace it called Isolate.kill(immediate) while the worker was INSIDE a synchronous native eval (worker dequeues commands sequentially, so 'shutdown' waits behind qjs_eval); the killed isolate enters teardown on the worker thread ("Cannot invoke native callback while unwind error propagates"), and the still-running eval's next worker-owned bytes dispatch (__jsrSendCopy/__jsrSkinBytes/__jsrMorphBytes via registerHostBytesFn → qjs_bytes_dispatch) failed dart::FfiCallbackThreadChecks → dart::Assert::Fail → abort. FIX = LIFECYCLE: kill on ack-timeout REMOVED entirely — the worker is now ORPHANED (messages land on closed ports, generation guards protect the new engine; it drains its eval, processes the queued shutdown, closes its runtime, exits). The ONLY remaining kill is the spawn-handshake path (commands==null ⇒ no 'run' ever sent ⇒ no runtime/callbacks) — the only safe kind. Also: _QuickJsWorker._run now closes a replaced runtime instead of dropping it, close() nulls the field; @visibleForTesting static shutdownAckGrace (default 10s) lets tests exercise the stuck path fast. Regression: test/js_isolate_worker_shutdown_test.dart — pre-fix SIGABRTs the flutter_tester subprocess (verified: identical DLRT stack), post-fix passes; app soak: profile build, JSR_THREE_AUTO=350 auto-cycler, 429 switches / 116 shutdowns (3 orphaned at the 10s grace — each was a pre-fix kill) / 0 aborts. 24+55 focused three/isolate tests green; adapter_test.js green. UPSTREAM ASKS for quickjs_runtime (~/git, user-owned, HOSTED dep so jsr can't fix locally): (1) expose JS_SetInterruptHandler for cooperative eval abort; (2) QuickjsRuntime.close() frees the runtime BEFORE closing callables (finalizers-during-destroy hazard); (3) g_bytes_callbacks/g_callbacks entries are never unregistered on close (stale entries persist for the process lifetime).
