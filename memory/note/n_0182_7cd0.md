# Note: n_0182_7cd0

FPS probe methodology for three widgets on macOS: example/lib/probe_fps.dart boots one prepared widget Release fullscreen; run via `JSR_WIDGET=three-interactive-cubes [JSR_STORM=1] ./build/macos/Build/Products/Release/js_widget_runtime_example.app/Contents/MacOS/js_widget_runtime_example` (JSR_WIDGET takes the WIDGET id like three-interactive-cubes, NOT the exampleId; JSR_THREE_EXAMPLE only works for the catalog app). JSR_R1_TIMING=1 prelude wraps renderer internals and prints "THREE probe r1timing:" per-phase ms (fastNodeMs/ensureMaterialMs include nested wrapped calls); probe prints static then storm windows and exits itself (~40s; kill leftovers with pkill -f js_widget_runtime_example). The storm Timer is frame-rate limited (~25Hz) — probe_fps now dispatches 4 back-to-back events per tick (~100Hz) to emulate real OS pointer flooding. Logs must go straight to a file (piping through grep eats output when the timeout kills the pipeline).
