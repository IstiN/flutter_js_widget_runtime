# Note: n_0139_a01b

Webcam backdrop invisible (2026-11-04): ROOT CAUSE = R1 GPU encoder lacked three.js's per-object winding flip for mirrored world matrices (matrixWorld det<0, e.g. the webcam examples' selfie mirror scene.scale.x=-1) — FrontSide meshes were back-face culled GPU-side, so the backdrop plane AND the whole facecap face rendered glitched (seams, missing nose, floating jaw). Fixed in flutter_gpu_three_backend.dart _threeCull/_threeShadowCull (determinant-aware cull flip); regression test test/golden/js_three_mirror_winding_golden_test.dart (run with --enable-impeller --enable-flutter-gpu --dart-define=JSR_THREE_GPU_GOLDEN=true). SECOND root cause: jsr-shot.app ad-hoc re-signing changes the cdhash, so the macOS TCC camera grant stops matching — AVCaptureDevice.authorizationStatus returns notDetermined (auth=0) even with an allow row in TCC.db, and requestAccess waits forever (no visible prompt) → camera.start never resolves. NSLog is invisible for open-launched release builds of this app; Swift breadcrumbs must write to JSR_CAMERA_LOG directly (implemented in MainFlutterWindow.swift). No codesigning identities exist on the keychain, so every rebuild needs a fresh TCC grant (owner action: tccutil reset Camera com.example.jsWidgetRuntimeExample + Allow once).
