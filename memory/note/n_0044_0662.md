# Note: n_0044_0662

js_widget_runtime 0.4.126 published (commit 8d37444, tag v0.4.126, CI green): new `jsr_widget` CLI for headless widget verification — `dart run bin/jsr_widget.dart test <dir> --event <id> --expect-state '<json>' --json` (QuickJS backend, no rendering, machine report, exit 0/1) and `... screenshot <dir> --out x.png` (production renderer → PNG). Architecture: Flutter-free core in lib/src/tooling/jsr_widget_tool_core.dart (spec/args/matchers/pub-cache QuickJS discovery); harness tool/jsr_widget_harness*.dart runs as flutter test with a JSR_TOOL_SPEC env contract; bin wrapper resolves the jsr package root from ANY consumer's package_config.json (rootUri resolves relative to .dart_tool/, a gotcha that cost a debug round). Works from any depending project; flutter on PATH required. Gotchas hit: `dart run` in this package trips native-assets build hooks (use `dart bin/...` via the Flutter dart SDK instead); toByteData(png) must run inside tester.runAsync (fake-async hangs); eventParts record equality in tests must compare flattened fields. The fa `jsr` CLI is proposed to surface these as `jsr widget:test`/`jsr widget:screenshot` pass-throughs (goal_builder coordinated).
