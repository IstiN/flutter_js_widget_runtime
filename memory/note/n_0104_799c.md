# Note: n_0104_799c

FIXED (2026-10-30): rapid module-switching SIGABRT crash in the three_example app — dart::FfiCallbackThreadChecks assert (abort() via DLRT_GetFfiCallbackMetadata ← quickjs_bridge qjs_dispatch ← JS_CallInternal). Mechanism: the isolate QuickJS worker processes commands SEQUENTIALLY, so during the synchronous JS_Eval of a just-booted widget bundle a 'shutdown' message cannot be processed; dispose() used to wait only 200ms for the ack and then Isolate.kill(immediate) — ripping the worker apart with qjs_dispatch on the C stack and corrupting the shared FFI callback registry, so the NEXT engine's host dispatch resolved to a stale registration → thread-check assert → whole-app SIGABRT. Fix (lib/src/runtime/js_widget_engine_quickjs_isolate_vm.dart dispose): graceful ack window 200ms → 2s (covers real bundle evals; kill(immediate) stays as the stuck-eval backstop), with the crash chain documented in a comment. UPSTREAM ASK for quickjs_runtime (~/git/quickjs_runtime, user-owned): (1) expose JS_SetInterruptHandler so a worker can abort a running eval on shutdown instead of relying on timeouts; (2) make the qjs_dispatch FFI callback registry robust to isolate teardown (per-runtime table reset / no cross-runtime id reuse). Related prior incident (same file, native bytes lane comment): sustained TransferableTypedData traffic raced the marker → SIGBUS; lane disabled. Repro was: rapid sidebar clicking; verified by stack, fixed build = rel10.
