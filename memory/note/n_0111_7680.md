# Note: n_0111_7680

Porting official three.js examples to JSR R1 (recipe proven on 48): (1) add a definition to EXAMPLES in tool/three_example/prepare.mjs — expected.html = sha256 of the official .html, expected.module = sha256 of the inline <script type="module"> bytes; assets = every 'textures/…'/'models/…' literal plus files referenced INSIDE .mtl etc (missing assets = silent async-init stalls with zero logs); raw models use mime application/octet-stream (text/plain is rejected). (2) add the id to the allowlist in bin/jsr_three_example.dart. (3) node tool/three_example/prepare.mjs <id> — only adapter changes require re-preparing; three.native.js runtime changes apply to all widgets on the next build (node tool/three/build.mjs --source /tmp/jsr-three-r186). (4) batch-verify headless with test/zz_batch_test.dart + ThreeQuickjsExampleHarness (zz_* excluded from git via .git/info/exclude); silent NO-FRAME with no logs = sync init throw — wrap widget.js in try{…}catch(e){console.error(…)} to surface it. Adding protocol bits: widen the Dart decoder mask (js_three_protocol.dart 'unknown material flag') or EVERY example regresses with 'dropped THREE packet' + 'first surface sequence must be 1'. New sidebar entries = enhanced-enum values in example/lib/three_example.dart (mind the terminating semicolon) + sidebarOrder + example/pubspec.yaml asset dirs. Check existing contract tests before degrading a previously-rejected capability (displacementMap rejection test forced scoping the degrade to MeshNormalMaterial).
