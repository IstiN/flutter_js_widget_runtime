# Note: n_0025_e56a

Motion-Canvas port (yoclip issue #1) CLOSED both sides: Layer 1 = jsr 0.4.114 (commit 57b4c24) jsr.motion.{tween,mapRange,clamp,wave} + ease additions (cubicBezier via Newton-Raphson+bisection); Layer 2 = jsr 0.4.115 (commit c02a508, published on pub.dev) shape nodes rect/circle/line/polygon in lib/src/renderer/nodes/js_shape_nodes.dart. Pins honored: rect/circle size exactly to their box with inside strokes (Container semantics); line/polygon size to tight geometry bounds + stroke inset, painted at node origin; polygon.points flat [x,y,...] (>=3 pairs, trailing odd number ignored, numeric strings tolerated); line only x1/y1/x2/y2; opacity multiplies ink alpha; no fill AND no stroke -> SizedBox.shrink. UiViewTreeNormalizer maps PascalCase aliases (render switch stays exact-match — hosts render canonical types; normalizer is bindings-only). yoclip integrated via passthrough (their bacbe2a, core 404/player 462 green); sequence stayed yoclip-side as lib/animation.js (their 7fed26b) per the scope agreement; their runtime prepends kJsWidgetBootstrap before evals (their FFI has no host channel — no-op sendMessage shim). Possible follow-ups if decks surface them: stroke outset for thick outlines, non-integer polygon points. CRAP ratchet lesson: new CustomPainter.shouldRepaint need branch-covered repaint tests or they fail the gate at 0% coverage.
