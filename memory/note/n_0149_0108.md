# Note: n_0149_0108

REGRESSION ROUND 2026-11-04 (tsl-skinning lane) root causes + restores: (1) SKIN PACKET STALE-STAGING BUG (caught by the skining-morph parity pin, 0.038 vs 2e-5): the skin packet's position/normal regions are IN-PLACE transform buffers — applyThreeSkiningPacket OVERWRITES them with the skinned result, so staging the pristine bind pose ONLY at packet build made call N+2 skin call N's OUTPUT (compounding drift: exploded poses also re-triggered the IK head cull bound and would have distorted Michelle over time — alive-only pins cannot see it; parity pins can). FIX in native_renderer.js _applySkining: packet.set(basePos/baseNormal) re-staged before EVERY native call (static-once regions are only indices/weights). Diagnostic method that cracked it: wrap __jsrSkinBytes, SNAPSHOT the input region BEFORE the call, JS re-skin from the snapshot, compare (wrapper must snapshot pre-call — post-call data is the output). LESSON: in-place Dart lanes must never cache input regions that double as output regions. (2) The working tree had LOST the uncommitted 11-02/11-03 shutdown lifecycle (kill-on-ack-timeout was back in _shutdownWorkerLocked; shutdownAckGrace/debugDrainStop* missing → 2 test files didn't compile): RESTORED into js_widget_engine_quickjs_isolate_vm.dart — @visibleForTesting static shutdownAckGrace (10s default), kill removed (orphan: closed ports drop messages, generation guards, worker drains + self-exits; only spawn-handshake kill remains in _startWorker), process-global drain stop armed BEFORE queuing 'shutdown' + cleared in finally, debugDrainStopSupported/Requested/debugSetDrainStop statics via a lazily-bound QuickjsFfi probe, _QuickJsWorker.close() nulls the field and _run CLOSES a replaced runtime. Bumped quickjs_runtime ^0.4.8→^0.4.9 (published for the drain stop; 0.4.8's prebuilt pub-cache .so lacks qjs_request_drain_stop → drain-race tests only SKIP; 0.4.9 has no prebuilt .so so QuickjsFfi falls to the native-assets hook dylib which HAS the flag → drain-race suite RUNS green, not skipped). Both suites green: worker_shutdown 2/2 (orphans outlive the 250ms grace, next engine renders), drain_race 3/3 (dispose<1500ms, chain frozen, flag released). (3) mirror-winding goldens were NEVER red on this tree — they require runner flags (--enable-impeller --enable-flutter-gpu --dart-define=JSR_THREE_GPU_GOLDEN=true); without them the harness dies 'Flutter GPU requires the Impeller rendering backend' (presentedFrames 0, backendInitializing 1) which LOOKS like a render regression. Both cases green with flags (redPx 65536 each). (4) marchingcubes 'resolution-20 bound' test (UNTRACKED, prior segment) is a DOCUMENTED PRE-EXISTING known-red (consolidation memory): the bound never existed in any commit/lane — official webgl_marchingcubes pins resolution 28 → vertexCount 10386 is the OFFICIAL default; a clamp would violate the byte-exact official-module fidelity contract. NOT downstream of the bytes/encode/bundle changes. Also: bundle rebuilt twice (skining fix) + bulk_reprepare 303/303 0 failures outputs byte-stable both times; tsl perf pin after the fix: tickAvgMs 4.78 (was 16.5 — the 0.4.9 native-assets dylib is faster than the 0.4.8 pub-cache .so for the main-thread backend), bytesPerEnvelope 867804 unchanged, skinCalls=jsFrames.
