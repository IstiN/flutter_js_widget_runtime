# Note: n_0105_f514

PERF (2026-10-30, commit 4b27462): webgl_helpers was ~16fps — root-caused and fixed 2.6x (~42fps). Profile method: kDebugMode probes (JSBOOT in the isolate backend for boot phases; temporary R1FRAME/R1EMIT/R1GEOUP/R1GEODIFF probes in native_renderer.js _render/_emit/_ensureGeometry — measure, then revert). Findings: (1) per-frame geometry signature strings for every drawable = pure QuickJS string churn (tens of KB garbage/frame, ~20ms of the 40ms tick); (2) upstream helpers (SpotLightHelper/CameraHelper/...) rewrite geometry in update() and set needsUpdate EVERY frame even when content is byte-identical — attribute.version bumps 2->3->4... and the old signature logic re-uploaded two 222KB line geometries EVERY frame through the b64 JSON lane. FIX: _geometrySignatureCached in native_renderer.js — per-geometry cache keyed on attribute/index versions; version moved -> FNV-1a hash (attributeContentHash) of the raw storage, matching hash = same content -> reuse signature (skip upload); only genuinely different content rebuilds. Result: geometryUploads 197->13 (one per geometry), presentedFrames 93->245 same window, GPU goldens byte-identical. REMAINING perf roadmap (not done): (a) 60ms-осталось ~24ms tick = traverse + genuinely-dynamic content; (b) b64 JSON lane per frame (~10-16ms for big frames) — real fix is reviving the native bytes lane, blocked by the quickjs_runtime SIGBUS incident (TransferableTypedData::New racing the marker — upstream ask); (c) boot ~1.1s = DOUBLE three eval (engine bundle 719KB + 609KB inlined in every prepared widget) — fix = persistent worker runtime reuse + prepared widgets not inlining three when the host provides it; (d) matcap/toon stay OUT of the expanded suite (headless fixture has no official texture assets) but ARE in the app sidebar — app runtime renders them.
