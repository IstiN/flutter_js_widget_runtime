# Note: n_0045_8619

js_widget_runtime 0.4.127 published (tag v0.4.127, CI green, merge a50e028 = PR #3 from the ai-teammate bot): new `voxel` renderer node — chunked voxel worlds on a pure-Dart software rasterizer over CustomPaint (no native deps, works on every backend); widget JS owns the world through CORE `voxel.*` host calls (intercepted before the host handler): `voxel.attach` probe (older runtimes reject → graceful degradation), `voxel.mesh {id, key, origin, positions, colors, indices}` pushes one chunk's flat vertex arrays (re-push only dirty chunks), `voxel.camera {id, position, yaw, pitch, fov?, light?, skyColor?}` (Minecraft yaw/pitch). Example: example/widgets/voxel-sandbox/. The bot's PR self-documented skills/AGENTS/CHANGELOG — future PRs from it can be trusted to carry docs. fa_widgets catalog mechanics (correction of my earlier mental model): widgets/ holds ONLY overlay.json pins (26 total) — external widgets carry source:{repo,commit}, VENDORED jsr widgets (video-player, pomodoro, voxel-sandbox...) have NO source block and pull code from the vendor/js_widget_runtime submodule pin (drift guard forbids id/version in their overlays); the vendor pin therefore controls what vendored widget versions the catalog serves. voxel-sandbox added as a vendored overlay pin (minRuntime 0.4.127) — catalog now 26 widgets.
