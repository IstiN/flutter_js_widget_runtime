# Note: n_0090_fa29

Approved three.js R1 example roadmap (user decision 2026-10-29): integrate official examples hardest-first, in waves. Wave 1: webgl_clipping (native clipping planes in three_r1.vert/frag + shadow pass, localClippingEnabled + material.clippingPlanes, lil-gui sliders), webgl_points_sprites (PointsMaterial.map + TextureLoader PNG, point-quad texture sampling + alpha discard), webgl_instancing_performance (needs a REAL dropdown node added to the JSON renderer + lil-gui options facade; mesh.count 1..10000 stress), webgl_geometry_text (FontLoader + TextGeometry, .typeface.json fonts pin from examples/fonts/ like panorama PNGs), webgl_geometry_shapes (Shape/holes/ExtrudeGeometry, pure JS). Wave 2: webgl_lod (LOD + FlyControls adapter, fog already in protocol), webgl_geometry_extrude_splines (TubeGeometry + dropdowns), webgl_raycaster_texture (raycast uv + Canvas2D painting onto CanvasTexture, needs dynamic texture re-upload), webgl_buffergeometry_drawrange (setDrawRange; rangeStart/rangeCount already in the geometry model). Long-term vision after waves (user wants NATIVE ANALOGS, not literal WebGL paths): post-processing/EffectComposer, ShaderMaterial-class custom shaders, video, audio, model loaders (GLTF/FBX), HDR/EXR/KTX2 textures, skinned meshes, morph targets — each opens a pipeline floor: RT (render-to-texture) is the keystone for portal/postprocessing/IBL-PMREM (instancing_dynamic needs PMREM env); multi-camera-in-frame (webgl_camera setScissor/setViewport); BatchedMesh opcode (webgl_mesh_batch); spot/point shadows (per-light shadow maps). Selection policy stays: byte-exact pinned official modules, no rewriting/approximating, unsupported features fail loudly (three.unsupported). 299 webgl_* total: 159 hard-skip today, 140 candidates.
