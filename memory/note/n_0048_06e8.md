# Note: n_0048_06e8

fa_craft 0.2.0 (commit 0b06c0a): ported the viewport to the bridge-owned voxel node (jsr 0.4.127+) — the diagnosis of the web-preview crawl was the legacy scene3d adapter re-sending ALL chunk mesh JSON (hundreds of KB) through jsr.render EVERY frame (worker postMessage + parse + diff). Native path: voxel.mesh per dirty chunk (once), one ~150B voxel.camera per frame, aim highlight as resident '__hl' chunk (zero-area quad when unaimed — runtime has no voxel.chunkRemove yet). Gotchas: (1) world.ensureArea re-marks w.dirty every frame for chunks missing from w.meshes, which the legacy path never fills — native uploads write a sentinel `w.meshes.set(key, true)` to stop infinite re-upload; (2) widget-side hostCalls must swallow rejections (fire-and-forget) or node tests/edge hosts wedge the loop; (3) exportState must NOT be throttled per-frame — IT tests (and CLI snapshots) read exported state after 1 pumped frame. Legacy scene3d path kept as fallback (voxel.attach rejects on older runtimes; harness boots it with voxelNative:false). Goldens stay pinned to jsr 0.4.126 → they keep validating the legacy path. Profiling: Facraft.prof (hud/mesh ms, uploads, meshKB) in exportState + F3 overlay + `[facraft]` console summary every 300 frames. Preview.dart `_submoduleWidgetBases` pin must move in lockstep with the fa-craft submodule pin (currently 0b06c0a).
