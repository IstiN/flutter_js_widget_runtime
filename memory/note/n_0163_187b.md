# Note: n_0163_187b

Probe A/B gotcha (2026-11-05, shadowmap-performance wave): a release probe binary bakes the asset SNAPSHOT at build time, and mid-wave rebuilds of assets/three/jsr_three_native.js by another agent (R1_VERSION bumped 7→8 in tool/three/src/r1.js while Dart latestR1Version is still 7) make binaries built AFTER the bump render NOTHING (every packet: 'dropped THREE packet: unsupported R1 version 8', presentedFrames=0, probe exits 6 via timeout). Note the dedicated js_three_flutter_js/quickjs tests hit the same wall, but the example APP still renders because the prepared widget's inlined three copy (widget.js) stays on the older protocol. A/B fix: cp -R the built .app to /tmp, overwrite the binary's copy at Contents/Frameworks/App.framework/Versions/A/Resources/flutter_assets/packages/js_widget_runtime/assets/three/jsr_three_native.js with git show HEAD:assets/three/jsr_three_native.js — repo untouched, app renders again. Adaptive directional-shadow refresh SHIPPED in flutter_gpu_three_backend.dart (host flag adaptiveShadowRefresh, dart-define JSR_THREE_SHADOW_ADAPTIVE, default ON; N 1→3 via 6-sample rolling pump-cadence window, raise >16ms / reset <12ms; defer only when map valid + dims unchanged; diagnostics shadowRefreshInterval/shadowDeferredFrames). Verified on webgl_shadowmap_performance (1512x867@2x): interval hits 3, ~30/46 frames deferred, renderedShadowDraws 157→~55 (2.9x) per 2s window; PNG captures byte-equivalent shadows vs legacy. FPS stayed ~21.5-21.8 for BOTH legacy and adaptive because the box was CPU-throttled by concurrent wave builds (Dart frameMs <1ms — limiter is the JS/morph tick, not GPU); on an idle box per the trusted 22ms-GPU diagnosis the ~2/3 shadow-pass cut (~5-7ms/frame) is what lifts the 44-52fps ceiling toward ~60fps.
