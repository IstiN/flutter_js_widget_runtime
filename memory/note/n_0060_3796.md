# Note: n_0060_3796

js_widget_runtime perf lane shipped (commit f74166b → publish): `jsr.b64encode(u8)` (ES5 base64, byte-exact with Dart) + `jsr.hostCallBinary(name, b64)` — fire-and-forget `__jsr_host_call_binary` raw-id channel → `JsRuntimeConfig.onHostCallBinary(name, Uint8List)`; no JSON body parse, no promise; wired through bridge + flutter_js/quickjs/web-worker engines (raw-id unwrap lists in BOTH engines + explicit bridge constructor pass-through — the engine constructors build JsWidgetBridge with explicit fields, a new config handler must be added there too or it silently arrives null). Measured (QuickJS macOS): JSON hostCall 0.92/2.63/8.75 ms per 100/300/1000-transform frame vs binary lane 0.30/0.86/2.83 — constant 3.1×, transport+promise floor only 0.06 ms. Bench lives in tool/perf/js_bridge_bench_test.dart (run explicitly, not in default suite). 699 tests, 21/21 example widgets boot, gates green.
