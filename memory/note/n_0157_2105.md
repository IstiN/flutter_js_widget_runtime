# Note: n_0157_2105

Interactive-fps collapse hypothesis for BatchedMesh widgets (measured on a throwaway probe build): static fps 120 (2097152 tris, frameMs 0.145ms), but dispatching pointer moves into the canvas at ~125Hz collapsed fps to 0-4. Cause: R1 BatchedMesh adaptation proxies keep the default Mesh/InstancedMesh raycast, so each pointermove re-tests every proxy's full triangle range (~2.1M triangle tests per event in QuickJS) on top of the module's own BVH raycast. Fix candidate (implemented then reverted with the experiment, never re-landed): set proxy.raycast = function() {} in tool/three/src/native_renderer.js proxy lane — the module's raycaster already walks the BatchedMesh itself.
