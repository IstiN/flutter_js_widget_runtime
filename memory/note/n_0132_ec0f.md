# Note: n_0132_ec0f

FIXED (2026-11-03): webgl_loader_pdb molecule switching was a silent no-op — root cause is the CSS2DObject 'removed' listener in the three.js bundle: `element instanceof element.ownerDocument.defaultView.Element`. The R1 JsrThreeDocument.defaultView shim (tool/three/src/runtime.js) had NO Element constructor, so `instanceof undefined` THREW inside Object3D.remove() the moment the pdb example's clear loop (`while(root.children.length>0) root.remove(root.children[0])`) hit the first CSS2DObject label; the loop aborted after exactly one object (observed: −320 tris = one icosahedron atom per click), PDBLoader.load never ran, gui value never updated, zero console errors. Fix (upstream-shaped): bounded marker class JsrThreeDomElement exposed as defaultView.Element/HTMLElement/Node + example_adapter.js localElement() puts shim elements on its prototype chain (Object.setPrototypeOf). After fix, switching works: caffeine(24 atoms+25 bonds=49 draws/7980 tris)→Ethanol(9+8=17 draws/2976 tris)→cubane.pdb(16+20=36 draws/5360 tris)→back to Caffeine, verified in test/js_three_loader_pdb_example_test.dart (drives harness.backend.callEvent with the LABEL value 'Ethanol' — exactly what the Flutter dropdown sends; labels map to allowed values via the lil-gui facade) and GPU eye-check pdb-before/after-switch.png. NOTE: the pdb dropdown DISPLAYS the first item ('Ethanol') even at boot on caffeine — pre-existing cosmetic facade quirk (row value='caffeine.pdb' filename vs items=labels; no match → shows items[0]); scene is correct; not a switching defect.
