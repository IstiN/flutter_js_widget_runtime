# Note: n_0169_ccf1

three-* reference widgets on the web preview: createWebThreeHost() MUST be given an assetLoader — without it every three.asset host-lane request fails with 'three.assetFailure: no three.asset loader is configured' and the widget renders an error card ('many don't load' on the site). The loader resolves the canonical pinned URL against the widget's assets.json (url -> file mapping, '/' flattened to '__') and fetches bytes over HTTP from raw.githubusercontent because the preview build does not bundle widget files. Native side equivalent: example/lib/three_widget_assets.dart (rootBundle). The prepare_manifest.json of each three-* widget pins the sha256 of tool/three_example/prepare.mjs — ANY edit to prepare.mjs invalidates every manifest; regenerate with `node tool/three_example/prepare.mjs <example-id> --source /tmp/jsr-three-r186 --offline` (CI verifies webgl_geometry_minecraft).
