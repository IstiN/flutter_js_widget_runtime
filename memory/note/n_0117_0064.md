# Note: n_0117_0064

THREE runtime-issue batch 2 DIAGNOSED+FIXED (2026-11-02): (1) webgl_panorama_cube white-screen stall ROOT CAUSE: single pinned 8192x1024 atlas (NOT 6 PNGs; asset was already sha256-pinned) → decodeImage returns 33.5MB RGBA as a 44.8MB b64 string → QuickJS worker stalls ~9-10s (decodeBase64 per-char indexOf+push loop 4.3s + three full-string regex passes ~1.05s + six 1024x1024 bilinear drawImage slices 2.2s) while RAF pump freezes (presentedFrames stuck at 3, textureUploads 0), then renders at 120fps. FIXED in tool/three/src/runtime.js decodeBase64 (fused charCodeAt+pair-table fast path, decodeBase64Slow fallback keeps exact semantics incl. clean-length %4, urlsafe, stop-at-first-=, assetFailure messages; 4019-case fuzz vs historical impl byte-identical) → 2.2s; and tool/three_example/example_canvas2d.js drawImage identity-1:1 fast path (per-row opaque → typed .set() row copy; else exact source-over blend; non-1:1 still bilinear for terrain-raycast) → 4ms. End-to-end white window now ~6s (remaining = b64 decodeImage lane itself: native jpeg decode + Dart b64 encode + 45MB isolate crossing + 24MB packet b64encode 0.56s — binary-lane work is the documented future fix). App captures: v1 presentedFrames 3/white; v3 (JSR_EXTRA_WAIT=14) full sun_temple panorama, textureUploads 6, textureCacheHits 6318, presentedFps 119.88.
