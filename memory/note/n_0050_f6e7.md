# Note: n_0050_f6e7

rAF timestamp bug class (fixed in js_widget_runtime commit 77637a8): JsWidgetBridge's JsRafScheduler used to send the Flutter Ticker's elapsed-since-start as the JS rAF timestamp. The scheduler STOPS the Ticker on any idle frame, and a web worker's rAF re-request round trip routinely misses a vsync under load → Ticker restart → elapsed reset to 0 → widget dt went negative → clamped to 0 → frame moved nothing. Symptom: 'runs fast for a second, then ~2x slower' (fa-craft W key). Fix pattern: fold ticker restarts into a monotonic epoch base BUT keep the Ticker's own clock (it is the fake clock under flutter_test — a wall Stopwatch freezes game time in pumped tests and broke the 3d-game-dodge score test). Related diagnostic trio in console: [facraft] JS ms / [voxel] paint ms+tris / [jsr-bridge] per-channel counts. Also: publish.yml concurrency group 'publish-main' can be wedged for hours by an orphaned in_progress runner (zero log output) — gh run cancel <id> unblocks the queue.
